# CLAUDE.md

Инструкции для Cline (Claude Code) при работе над проектом **Гант** (gantt-диаграмма задач).

## Обязанности

При любых изменениях в коде проекта Cline обязан:

1. **Проверять согласованность с документацией** — после каждого изменения сверять затронутые файлы с `README.md` (структура проекта, API, модель данных, компоненты, утилиты, конфигурация).
2. **Обновлять документацию при необходимости** — если изменение затрагивает:
   - структуру проекта (новый файл/каталог, перенос, удаление);
   - API сервера (новый маршрут, изменение метода/формата ответа);
   - модель данных (`db.json`, `Issue.base`, `Issue.jira`, вычисляемые поля);
   - компоненты или утилиты (новые/изменённые/удалённые);
   - конфигурацию (`.env`, `src/api.ts`, настройки JQL);
   - зависимости, запуск, сборку;
   - поведение приложения (новые фичи, изменение логики).
3. **Добавлять в документацию новые фичи** — любую реализованную функциональность описывать в `README.md` (и при необходимости в `CLAUDE.md`).
4. **Синхронизировать README.md и CLAUDE.md** — если изменения касаются только процесса разработки/поддержки (например, новые правила для Cline), обновлять `CLAUDE.md`.

## Ключевые факты о проекте

- **Стек**: React + TypeScript (frontend), чистый Node.js `http`-сервер (backend), JSON-файл `db.json` (БД), REST API Jira v2.
- **Точка входа фронтенда**: `index.html` → `src/index.js` (монтирует `#app`).
- **Точка входа сервера**: `server/index.js` (маршрутизация по `req.url`).
- **БД**: файл `db.json` — сервер читает при старте (`server/db.js`), пишет через `set()/insert()` после мутаций.
- **Jira-интеграция**: `server/jira.js` — поиск по JQL (постранично по 100), обработка issues (`processIssue`), создание новой записи при первом появлении.
- **API_HOST**: `src/api.ts` собирает адрес сервера из `.env` — `WEB_SERVER_HOST` и `WEB_SERVER_PORT` (фоллбэк `localhost:7778`). Parcel подставляет env-переменные на этапе сборки, поэтому при смене порта достаточно обновить `.env`.
- **Синхронизация задач**: `db.updated` / `issue.updated` — временные метки; `Table` рисует вертикальную линию «обновлено».
- **Вычисляемые поля** (`firstDay`, `duration`, `plannedDays`, `days`, `isPlanned`) считаются на клиенте в `src/components/Table/utils.ts` `processIssue()` и **не** хранятся в `db.json`.

## Структура документации

- `README.md` — полное описание приложения: возможности, архитектура, структура, работа, модель данных, API, запуск, конфигурация, компоненты, утилиты, TODO.
- `CLAUDE.md` — этот файл: правила поддержки и синхронизации документации.

## Правила при внесении изменений

1. **Перед изменением** — ознакомься с соответствующим разделом `README.md`.
2. **После изменения** — обнови `README.md`:
   - при изменении структуры — раздел «Структура проекта»;
   - при изменении API — раздел «API сервера»;
   - при изменении модели данных — раздел «Модель данных»;
   - при изменении компонентов/утилит — разделы «Фронтенд: компоненты» и «Утилиты»;
   - при изменении конфигурации — раздел «Конфигурация»;
   - при изменении запуска — раздел «Запуск»;
   - при добавлении новой фичи — опиши её в «Возможности» и соответствующем разделе;
   - при решении TODO — переноси из «Известные TODO / особенности» в описание реализованного.
3. **Не удаляй документацию** ради сокращения — лучше актуализировать, чем потерять контекст.
4. **Комментарии** — помечай в коде TODO/FIXME с пометкой, если это незавершённая фича, чтобы её можно было отследить в README.
5. **Соблюдай формат**: таблицы для API/компонентов/утилит, блоки кода для примеров, списки для перечислений.

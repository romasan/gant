# Гант

Gantt-диаграмма для визуализации и планирования задач команды. Приложение тянет задачи из **Jira**, позволяет расставлять их на временной шкале, редактировать даты, длительность, исполнителей и синхронизировать изменения.

## Возможности

- **Загрузка задач из Jira** — по JQL-запросам с постраничной выборкой (`maxResults=100`), включая историю смены статусов (changelog) и целевые даты (`Target start` / `Target end`).
- **Gantt-таблица** — задачи в виде строк, каждый день — ячейка с цветовой индикацией статуса; шапка с датами, месяцами, выходными.
- **Планирование** — ручная установка даты начала, длительности (в рабочих днях), исполнителя.
- **Автоматическая длительность** — если в Jira заполнена оценка (`timetracking`) и задача начала разрабатываться — длительность считается автоматически от фактической даты старта.
- **Сортировка** — по исполнителю → статусу → дате начала; группировка строк по исполнителям.
- **Контекстное меню строки** — редактирование, сдвиг даты, изменение исполнителя, переход в Jira.
- **Команда** — управление составом команды, группами.
- **Настройки** — настройка JQL-фильтра (проекты, исключаемые типы/статусы, компоненты, спринты) и параметров отображения (выходные, разделители и т.д.).
- **Легенда** — расшифровка цветов статусов.

## Архитектура

Приложение состоит из двух частей:

```
┌───────────────────┐      HTTP / JSON       ┌───────────────────┐       REST API       ┌────────┐
│   Frontend (React)│ ─────────────────────▶ │  Server (Node.js) │ ───────────────────▶ │  Jira  │
│   src/            │ ◀───────────────────── │  server/          │ ◀─────────────────── │        │
└───────────────────┘      CORS + JSON       └───────────────────┘    Bearer-токен Jira └────────┘
                                                    │
                                                    ▼
                                            ┌────────────────┐
                                            │   db.json      │
                                            │ (JSON-файл БД) │
                                            └────────────────┘
```

- **Frontend** — одностраничное React-приложение (JS + TS). Точка входа — `index.html` → `src/index.js` (нативно через `<script type="module">`). HMR/дев-сервер запускается командой `npm run dev:web`.
- **Server** — чистый Node.js `http`-сервер без Express. Раздаёт данные из `db.json` и проксирует запросы в Jira REST API.
- **Хранилище** — файл `db.json` в корне проекта. Сервер читает его при старте и сохраняет после каждой мутации.
- **Jira** — интеграция через REST API v2 (`/rest/api/2/...`) с Bearer-авторизацией по токену.

> ℹ️ `src/api.ts` собирает `API_HOST` из `.env` (`WEB_SERVER_HOST`, `WEB_SERVER_PORT`). При смене порта достаточно обновить `.env` — и фронтенд, и сервер подхватят новое значение (Parcel подставляет env-переменные на этапе сборки).

## Как это работает

### 1. Загрузка данных

1. Пользователь открывает приложение → `App` вызывает `fetchData()` (`src/api.ts`) → `GET /start`.
2. Сервер (`server/api/start.js`) возвращает весь `db.json` + поле `host` (URL Jira из `.env`).
3. `App` хранит ответ в состоянии `data` и передаёт его в `Table`.

### 2. Первичная синхронизация с Jira

- `db.jql` хранит настройки фильтра: `projects`, `excludeTypes`, `excludedStatuses`, `components`, `sprints`.
- `server/jira.js` собирает JQL вида:

  ```
  project IN ('X') AND type NOT IN (...) AND status NOT IN (...) 
  AND component IN (...) AND (sprint IN openSprints() OR sprint IN ('...'))
  ```

- Постранично (по 100 шт.) запрашивает задачи из Jira с `expand=changelog`, обрабатывает каждую (`processIssue`) и **сливает** в `db.issues`:
  - задача уже есть (по `jira.key`) → обновляет её `jira`-часть;
  - новой задачи нет → создаёт запись с `base.summary = "KEY: summary"` и `jira`-данными.
- Пишет `db.updated` = текущее время.

### 3. Отображение в таблице

- `Table` фильтрует issues по команде (`teamFilter`), обрабатывает каждую (`processIssue` — считает фактическую длительность, `plannedDays`, цветовые статусы по дням), сортирует (`sortTable`) и рендерит строки.
- Для каждой задачи:
  - берётся история статусов из `jira.statuses`;
  - если найдена дата перехода в `develop`/`in progress` → задача «фактически начата»: длительность считается от timetracking (`jira.timetracking`) или от ручной оценки (`base.duration`);
  - если у задачи нет истории (или это плановая) → отображается по `base.startDate` + `base.duration` как «плановая» (пунктиром);
  - каждый день интервала раскрашивается в цвет текущего статуса на этот день.

### 4. Редактирование

- Через контекстное меню (клик по задаче) или модалку `TaskModal`:
  - меняем `base.startDate`, `base.duration` (в рабочих днях с учётом выходных), `base.assignee`, `base.summary`;
  - сохранение — `POST /issue` (server/api/issue.js), которое обновляет запись в `db.issues` по `id` или по `jira.key` или создаёт новую.
- Привязка к Jira: в модалке можно ввести `PROJECT-123`, сервер скачает задачу из Jira (`GET /issue?query=KEY`), и она сохраняется с полным `jira`-объектом.

## Модель данных

### db.json

| Ключ | Тип | Описание |
|---|---|---|
| `dateRange` | `string[]` | `[from, to]` — видимый диапазон дат |
| `projects` | `string[]` | Проекты (для JQL-фильтра и выбора в модалке) |
| `team` | `string[]` | Список участников команды |
| `issues` | `Issue[]` | Все задачи |
| `weekends` | `string[]` | Дополнительные выходные дни (кроме Сб/Вс) |
| `delimiters` | `string[]` | Даты-разделители на шкале |
| `updated` | `string` (ISO) | Время последней синхронизации с Jira |
| `jql` | `object` | Настройки JQL-фильтра: `projects`, `excludeTypes`, `excludedStatuses`, `components`, `sprints` |
| `groups` | — | Группы команды (при наличии) |

### Issue

```ts
interface Issue {
  id: string;              // uuid
  updated: string;         // ISO дата последнего изменения
  base: {
    summary: string;       // отображаемое название ("KEY: summary")
    startDate?: string;    // плановая дата начала (YYYY-MM-DD)
    duration?: string;     // плановая длительность в рабочих днях
    assignee?: string;     // исполнитель (или 'Не назначена')
  };
  jira: {
    key: string;           // "PROJECT-123"
    status: string;        // текущий статус
    summary: string;
    assignee: string;
    statuses: Array<{      // история смены статусов (из changelog)
      date: string;        // ISO
      from: string;
      to: string;
    }>;
    targetStart?: string;  // Target start
    targetEnd?: string;    // Target end
    timetracking?: string; // оригинальная оценка ("2w 3d 4h")
    createdDate?: string;
    updatedDate?: string;
    resolvedDate?: string;
    priority?: string;
    inSprint?: boolean;    // задача пришла из открытых спринтов
  };
  // Вычисляемые поля (добавляются на клиенте, не хранятся):
  firstDay?: string;
  duration?: number;
  plannedDays?: string[];
  days?: Record<string, string>;  // date -> статус для раскраски
  isPlanned?: boolean;
}
```

## API сервера

| Метод | Путь | Описание |
|---|---|---|
| GET | `/start` | Вернуть весь `db.json` + `host` |
| GET | `/issue?query=KEY` | Скачать задачу из Jira (обработанную `processIssue`) |
| POST | `/issue` | Создать или обновить задачу в `db.issues` (по `id` или `jira.key`) |
| DELETE | `/issue?query=ID` | Удалить задачу по `id` |
| GET | `/issues` | Массово обновить из Jira по сохранённому JQL (возвращает `{jql, added?, updated?}`) |
| PATCH | `/issues` | Пересинхронизировать выбранные задачи по ключам из payload |
| DELETE | `/issues` | Удалить задачи (по id в payload или все) |
| POST | `/list` | Сохранить произвольный список в БД: `{key, values}` → `db[key] = values` |
| POST | `/list/jql` | Сохранить настройки JQL: `{key, values}` → `db.jql[key] = values` |
| POST | `/randomJql` | Выполнить произвольный JQL: `{query}` → результат `getRandomJql` |
| OPTIONS | любой | CORS-preflight (все методы разрешены) |

Сервер также:
- пишет сырые ответы Jira в `tmp/issues.json` и `tmp/<KEY>.json` для отладки;
- логирует каждый URL в консоль;
- отвечает `{"debug": "=)"}` для неизвестных маршрутов.

## Запуск

### Требования

- Node.js (с `fetch` — Node 18+)
- Доступ к корпоративной Jira (`JIRA_URL`)

### Установка и запуск

```bash
# 1. Скопировать .env и заполнить
cp .env.example .env

# 2. Установить зависимости
npm install

# 3. Запустить фронтенд и сервер в режиме разработки
npm run dev:web      # фронтенд (index.html, HMR)
npm run dev:server   # сервер (nodemon, авто-перезапуск при изменении server/**/*.js)
```

Либо одной командой через `dev.sh` — он создаёт tmux-сессию `npm_starts` с двумя панелями (`dev:web` + `dev:server` в nodemon) и подключается к ней:

```bash
./dev.sh
```

Сервер слушает `WEB_SERVER_HOST:WEB_SERVER_PORT` из `.env`, фронтенд открывается в браузере.

## Утилиты

### `src/utils.ts`

| Функция | Описание |
|---|---|
| `countDaysBetween(a, b)` | Кол-во календарных дней между датами |
| `parseDurationToDays("2w 3d 4h")` | Парс Jira-оценки в рабочие дни (нед.×5 + дни + часы/8) |
| `isWeekend(date, weekends)` | Праздник/выходной (Сб/Вс + список `weekends`) |

| `expandWeekend(start, duration, weekends)` | Реальное кол-во календарных дней из `duration` рабочих, начиная с `start` |

### `src/components/Table/utils.ts`

| Функция | Описание |
|---|---|
| `getDays(dateRange, raw, weekends)` | Массив дней диапазона (с флагами выходных) |
| `getToday(range, date?)` | Смещение даты от начала диапазона (для линий) |

| `teamFilter(team)` | Фильтр по команде (включая «не назначено») |
| `processDay(day, list)` | Подсчёт загрузки участников по дням (`day.counts`) |
| `processIssue(issue, weekends)` | Вычисление `firstDay`, `duration`, `plannedDays`, `days` (раскраска) |
